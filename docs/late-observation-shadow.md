# Late official-observation shadow (isolated worktree, paper only)

Run only from an isolated research checkout with its own Python environment. **Do not run the funded checkout or edit its ledgers.**

```sh
python -m src.v3.late_public_probe --slug "$EVENT_SLUG" --market-id "$MARKET_ID" --output experiments/late-observation/new-public.json
python -m src.v3.late_observation --input path/to/operator-evidence.json --audit experiments/late-observation/new-audit.json
```

The CLI accepts exactly one JSON candidate, writes an exclusive-create immutable input/result audit inside this worktree, and never authenticates, trades or writes a ledger. If Gamma is malformed or the exact market is closed/inactive/not accepting orders, not uniquely present, or invalid despite its open flags, the public probe saves only bounded public URL/timestamp/market-ID metadata and a fixed-reason rejection **without** raw provider data, a replayable `input`, METAR request, or CLOB request. Both probe and audit output paths must resolve inside this worktree; existing files are never overwritten. The October 14 closed-market capture has been sanitized to bounded metadata and a hash of the original fetched event; new rejected probes do not retain raw event data. For open markets it queries Gamma event, YES CLOB book and AviationWeather KLGA METAR (read-only), saving their raw JSON plus fetch timestamps. It intentionally rejects: AviationWeather METAR `reportTime` is *observation time*, not independently established `published_at` and not necessarily the specified weather.gov **Hourly Data / Temp column**. Its report cannot be substituted as resolver evidence. No fabricated observations, model, or final high are included.

Operator evidence must include the raw market and `market_fetched_at`, market ID, condition ID, YES token ID, canonical `rule_sha256`, `rule_kind=hourly_temp_whole_degree`, local `target_date`, Gamma `target_end_date`, resolver `station_id`, explicit primary-source availability, active/open flags, `decision_at`, and a nonempty `observations` array. Each observation must carry exact rule `source_url`, `hourly=true`, `column=Temp`, matching station, timezone-aware `observed_at` and **independently established** `published_at`, and whole-degree `temperature_f` (or `temperature_c` for Celsius rule). `remaining_day_model` must include station, date, exact `market_id`, `condition_id`, YES `token_id`, `outcome=Yes`, `bucket` equal to the exact Gamma market question (including its bucket wording), `rule_sha256` equal to the candidate's canonical raw Gamma snapshot hash, `issued_at`, `published_at`, source URL, conservative `probability_lower` for that **specific bucket**, and a plausible remaining-day maximum (scenario, NOT a proven cap). Missing or mismatched bindings fail closed; supplying these fields is an assertion, not independent verification that a real model was calibrated for this outcome. Also provide YES `book` with matching token/condition, `timestamp`, `fetched_at`, bids, asks, tick and minimum order size; `shares`, `latency_seconds` (1–60), fee rate at least 0.05, and `fee_verified_at` plus `fee_source_url=https://docs.polymarket.com/trading/fees`. See synthetic test fixture in `tests/test_late_observation.py` for schema only; never use it as actual market evidence.

A candidate is rejected for missing/late publication, mismatched source/station/day/token/hash, missing/invalid/mismatched Gamma `endDate` versus `target_end_date` (same timezone-aware instant required), a Gamma market snapshot that is not explicitly active, open, and `acceptingOrders=true` (regardless of separately supplied flags), stale observation/model/book, no bids/asks, crossed book, insufficient half-depth, minimum size, or non-positive lower-bound edge after an extra ask tick and quadratic taker fee. Running high above a bounded bucket permanently eliminates YES for that bucket under unchanged rules, but running high *inside* a bucket does not establish outcome: later readings and rule corrections remain possible. A lower bound supplied by an operator is **not** calibrated or independently verified by this code; synthetic eligible tests are not evidence of profitable edge. A one-tick latency allowance is a scenario, not a guarantee of a fill. No labels, fills, historical performance, or go-live conclusion are produced.

The public probe refuses HTTP redirects and caps streamed decoded response bodies before parsing: Gamma 1,000,000 bytes, METAR 256,000 bytes, CLOB 512,000 bytes; requests use 5-second connect and 15-second read timeouts (per read, **not** an end-to-end deadline). Rejected invalid/oversized responses persist bounded metadata only. For an open validated market, `evidence.book.data` preserves the native CLOB JSON unchanged: native `market` is the condition ID, `asset_id` the token ID, and `timestamp` is Unix milliseconds. `input.book` is a separate derived evaluator view: those IDs are copied only after exact matching to Gamma; the original millisecond timestamp is converted to an ISO UTC instant; `fetched_at` is the probe's book-response receipt time. Levels, tick and minimum size come directly from the native book. Missing/invalid native timestamp or wrong IDs reject without inventing a time or identity. Existing historical captures may still contain the earlier unconverted `input.book`; replay remains rejected before the book check when resolver evidence is missing.

October 12 genuine public sample: `experiments/late-observation/public-20261012.json` includes market 5482417, six public METAR reports and a YES book with 51 asks and **zero bids**. `replay-20261012.json` is rejected (`fallback resolver not ruled out`), before treating METAR as the exact resolver. Neither artifact attests an official hourly publication time or supports an eligible trade.

October 14 bounded public follow-up: `experiments/late-observation/public-20261014-closed-rejection.json` retains the original public URL, fetch timestamp, event/selected-market identity and actual flags for market 5540790 (`active=true`, `closed=true`, `acceptingOrders=false`), the original fixed-reason rejection, and the SHA-256 of the original canonical JSON Gamma event. The raw event was removed from the formerly 79,967-byte artifact; the digest is provenance, not a way to replay or independently verify the redacted event from this file. No METAR/CLOB was requested. This is rejection evidence only, not a publication-time check or final settlement label.

Sources/provenance: Gamma `https://gamma-api.polymarket.com/events/slug/highest-temperature-in-nyc-on-october-12-2026`; CLOB `https://clob.polymarket.com/book`; AviationWeather `https://aviationweather.gov/api/data/metar`; Polymarket fee formula `https://docs.polymarket.com/trading/fees`. No third-party code or dataset was copied. API data is public but access/redistribution remain subject to the providers' terms; this local evidence is not licensed by this project for republication.

## Persistent-capable public collector (not launched as a service)

From the isolated worktree, with the research Python environment:

```sh
python -m src.v3.late_public_collector --once --state-dir data/late-observation-worker
python -m src.v3.late_public_collector --state-dir data/late-observation-worker
```

The second command loops in the foreground until SIGINT/SIGTERM; **no service is installed or enabled**. Its state directory must be a subdirectory of ignored `data/` inside the isolated worktree and cannot contain symlinks; `data/` is ignored by Git. A persistent `worker.lock` uses nonblocking exclusive `flock` (do not delete it while the worker runs). Atomic `status.json` records running/completed/interrupted/skipped state, PID, heartbeat, cycle UTC start/completion, persisted last completed time, NYC event date, attempted/captured/eligible/rejected counts, fixed sanitized errors, provider health, and capture basenames. Restart and `--once` honor the persisted 30-minute interval from the previous completed cycle: an early call records `skipped` with zero request budget and makes no public request. An interrupted cycle does not reset the cadence; on restart an orphaned `running` state is marked interrupted before skip/run. Each cycle derives the current NYC calendar date (including DST), constructs the exact `highest-temperature-in-nyc-on-<month>-<day>-<year>` event slug, makes **one** bounded public Gamma GET, validates event identity/open flags and market question/date, and selects no more than the two numerically lowest exact open market IDs. There is no price-driven selection. One bounded existing probe subprocess per market may make at most one further Gamma, one METAR, and one CLOB request (maximum seven GETs per cycle: Gamma budget `1 + MAX_MARKETS`, METAR and CLOB `MAX_MARKETS` each; redirects refused and bytes capped). Each probe has a 75-second wall timeout; SIGTERM kills and waits for its separate process group before releasing the lock. Failure never triggers a busy retry. Capture files are exclusive-create and pruned oldest-first to 96 files and 128 MiB; malformed/untrusted probe output is removed. The state directory is private mode 0700 and state/lock/capture files mode 0600; symlinks are refused. Collector and probe disable Requests environment trust; the child receives only a minimal noncredential environment, not HOME, proxies or auth variables.

`captured` counts only probe records with retained Gamma, METAR and book response data and bound paper-only input, never a request failure, trade, or official observation. Rejected probes without complete evidence remain in bounded `rejection_files` and count toward `rejected`, not `captured`; `request_failure` counts transport/HTTP failures in probes separately. `eligible` is a synthetic-testable paper classification only; the current public probe cannot supply the independent official publication time or remaining-day model required to emit it in live use. Provider `no_response` means failure before a response, `interrupted` means the response stream failed, `http_error` means unsuccessful HTTP status, `malformed` means invalid/oversized bytes or shape, `error` means invalid discovery or probe failure, and `not_verified` means no retained evidence of a valid response, not a confirmed outage. METAR reports cannot establish resolver Hourly Data `Temp` publication time. There is no publication timestamp inference, settlement signal, model calibration, fill, P&L, credentials, or order flow. Review status and raw evidence locally before interpreting it; stop the worker rather than attempting service deployment without review.

# AWC evidence campaign (not launched)

This isolated worktree contains a **manual one-cycle**, public-only evidence collector, not a daemon or trading strategy. No scheduler/service is installed. It supports only OPKC / Asia-Karachi. An explicit config pins the October 28 identity and rule SHA-256. Alternatively `--discover-date` derives an exact daily candidate from one public Gamma read, checks the OPKC AWC source and rules, selects the unique Karachi lower-tail rung, and pins event/market/date/rule plus exact condition ID and ordered Yes/No token IDs in the append-only raw Gamma tape; subsequent cycles (including explicit-config cycles) reject pin drift. Legacy first rows derive the condition/token pin from their recorded raw Gamma response; missing or inconsistent evidence fails closed. First-seen discovery is **not** independent human review of a future rule. Do not infer a past observation or forecast from a later fetch.

For a reviewed one-shot invocation (not run as a service):

```sh
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign --report
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign
# Manual daily option only after reviewing candidate rules; do not schedule:
python -m src.v3.awc_campaign --discover-date 2026-10-29 --start-at 2026-10-27T11:00:00+00:00 --directory data/awc-campaign
```

`--report` reads the append-only tape without fetching. At most six public GETs per cycle: Gamma (shared with discovery), forecast, CLOB, AWC and, only after an available AWC response plus terminal Gamma payout, Data API token lookup and resolution. Each read has a 10-second socket / interrupting 12-second wall limit, a 60-second total cycle limit, no redirects/ambient proxies or credentials, and source-specific byte caps (Gamma 1 MB, forecast 300 KB, CLOB 512 KB, AWC 256 KB, each Data API 128 KB). The 16 MB serialized-row ceiling includes JSON escaping and metadata and is checked **before** publication; reads apply the same ceiling. At most 180 rows consume 2.88 GB of tape (excluding filesystem overhead). The 180-cycle, 45-calendar-day, and 30 same-venue-corroborated **unique event-day** caps are enforced before network. One event-hour is captured at most once. Output is restricted to the approved research root with no-follow descriptor walks and atomic exclusive append; old tape entries are never rewritten. The hash chain detects accidental/intermediate edits but not adversarial replacement of the last row. The first candidate manifest is pinned by a complete successful cycle, not by discovery alone; invalid discovery fails closed without publishing a row. No automatic scheduling or retries.

Successful captures retain HTTP status, exact UTF-8 response body, URL, SHA-256, request/acquisition times and response Date. AWC 204 or timeout retains upstream evidence as `captured_partial` and leaves observation/label unverified. Other upstream failures refuse an append. For terminal Gamma, Data API reads are persisted; timeout/malformed/unavailable replies are recorded as unverified, not silently promoted. A `venue_corroborated_final_binary` label requires Gamma binary payout, exact both CTF tokens' condition/event/slot/opposite identities and complementary Data API final prices, plus an exact `resolved` condition row ([public Data API contract](https://docs.polymarket.com/market-data/public-analytics#market-resolution)). The cap replays recorded Gamma and Data API bytes and validates token and condition resolution; a claimed label status, Gamma-only label or malformed Data API body never counts. Both APIs are Polymarket-operated: this is **same-venue corroboration, not independent on-chain UMA verification** or proof of AWC correction chronology or Weather Underground fallback. Open-Meteo forecast issue time remains unknown (`first_available_at` is receipt, never retroactive issuance). No label makes this live eligible.

**Launch blockers:** The first-seen daily rule and selected rung still need external review and an independently reviewed multi-day manifest; daily discovery failures (including absent Gamma/invalid rule) abort before a row, so a durable failure-attempt ledger and missing-day policy are not yet implemented. A historical Karachi October 22 public Data API crosscheck worked, but is not independent on-chain verification. AWC future-day 204 in the existing smoke is no observation. Forecast issuance timestamp and AWC correction-publication/cutoff chronology remain unproven; independent review of revised code and separate recurrence authorization are required. Do not launch recurring service or change funded execution/profile flags.

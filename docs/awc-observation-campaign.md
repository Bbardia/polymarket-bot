# AWC evidence campaign (not launched)

This isolated worktree contains a **manual one-cycle**, public-only evidence collector, not a daemon or trading strategy. No scheduler/service is installed. It supports only OPKC / Asia-Karachi. An explicit config pins the October 28 identity and rule SHA-256. Alternatively `--discover-date` derives an exact daily candidate from one public Gamma read, checks the OPKC AWC source and rules, selects the unique Karachi lower-tail rung, and pins event/market/date/rule in the append-only tape; subsequent cycles reject pin drift. First-seen discovery is **not** independent human review of a future rule. Do not infer a past observation or forecast from a later fetch.

For a reviewed one-shot invocation (not run as a service):

```sh
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign --report
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign
# Manual daily option only after reviewing candidate rules; do not schedule:
python -m src.v3.awc_campaign --discover-date 2026-10-29 --start-at 2026-10-27T11:00:00+00:00 --directory data/awc-campaign
```

`--report` reads the append-only tape without fetching. At most six public GETs per cycle: Gamma (shared with discovery), forecast, CLOB, AWC and, only after an available AWC response plus terminal Gamma payout, Data API token lookup and resolution. Each read has a 10-second socket / interrupting 12-second wall limit, a 60-second total cycle limit, no redirects/ambient proxies or credentials, and source-specific byte caps (Gamma 1 MB, forecast 300 KB, CLOB 512 KB, AWC 256 KB, each Data API 128 KB). The 180-cycle, 45-calendar-day, and 30 independently finalized **unique event-day** caps are enforced before network. One event-hour is captured at most once. Output is restricted to the approved research root with no-follow descriptor walks and atomic exclusive append; old tape entries are never rewritten. The hash chain detects accidental/intermediate edits but not adversarial replacement of the last row. The first candidate manifest is pinned by a complete successful cycle, not by discovery alone; invalid discovery fails closed without publishing a row. No automatic scheduling or retries.

Successful captures retain HTTP status, exact UTF-8 response body, URL, SHA-256, request/acquisition times and response Date. AWC 204 or timeout retains upstream evidence as `captured_partial` and leaves observation/label unverified. Other upstream failures refuse an append. For terminal Gamma, Data API reads are persisted; timeout/malformed/unavailable replies are recorded as unverified, not silently promoted. A final label requires Gamma binary payout, exact both CTF tokens' condition/event/slot/opposite identities and complementary on-chain final prices, plus an exact `resolved` condition row ([public Data API contract](https://docs.polymarket.com/market-data/public-analytics#market-resolution)). Gamma-only legacy labels do not count toward the 30-day cap. A matching Data API row is settlement corroboration, not independent proof of AWC correction chronology or Weather Underground fallback. Open-Meteo forecast issue time remains unknown (`first_available_at` is receipt, never retroactive issuance). No label makes this live eligible.

**Launch blockers:** The first-seen daily rule and selected rung still need external review and an independently reviewed multi-day manifest; daily discovery failures (including absent Gamma/invalid rule) abort before a row, so a durable failure-attempt ledger and missing-day policy are not yet implemented. Data API corroboration has not been exercised against a real finalized OPKC day. AWC future-day 204 in the existing smoke is no observation. Forecast issuance timestamp and AWC correction-publication/cutoff chronology remain unproven; independent review of revised code and separate recurrence authorization are required. Do not launch recurring service or change funded execution/profile flags.

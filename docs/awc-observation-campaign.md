# AWC evidence campaign (not launched)

This isolated worktree contains a **manual one-cycle**, public-only evidence collector, not a trading strategy. A separate one-shot recurrence runner and journal are documented in [awc-recurring-runner.md](awc-recurring-runner.md); no scheduler/service is installed. It supports only OPKC / Asia-Karachi. An explicit config pins the October 28 lower-tail identity and rule SHA-256 and leaves its existing manual tape unchanged. Alternatively `--discover-date` derives an exact daily candidate from one public Gamma read: it requires exactly 11 Karachi brackets (one lower tail, nine contiguous single-degree rungs, one upper tail), parses exact question grammar and date, validates every market's OPKC AWC source/rules, outcome tokens and condition, rejects duplicate IDs/degrees/conditions/tokens, sorts by numeric degree, and selects the single center-degree rung (October 28: 37°C; October 29: 36°C in the observed shapes). Unexpected counts, wording or gaps abort before collection. It pins event/market/date/rule plus exact condition ID and ordered Yes/No token IDs in the append-only raw Gamma tape; subsequent cycles reject pin drift. Neither forecast nor book price changes the selected rung. Legacy first rows derive the condition/token pin from their recorded raw Gamma response; missing or inconsistent evidence fails closed. First-seen discovery is **not** independent review of a future rule. Do not infer a past observation or forecast from a later fetch.

For a reviewed one-shot invocation (not run as a service):

```sh
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign --report
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign
# Manual daily option only after reviewing candidate rules; do not schedule:
python -m src.v3.awc_campaign --discover-date 2026-10-29 --start-at 2026-10-27T11:00:00+00:00 --directory data/awc-campaign
```

`--report` streams the append-only tape without fetching or retaining previous raw rows. A capture preflight makes one complete sequential replay inside its 60-second cycle, validating canonical bytes and the hash chain, replaying same-venue resolved-day evidence, and recovering target-day condition/ordered-token pins from raw Gamma; daily discovery passes that summary into collection rather than rescanning. Memory is bounded by one 16 MB serialized row and its transient JSON/canonical representations plus small counters/unique-day keys, not total tape size. The full tape must still be read, decoded and canonically re-encoded per invocation; at the maximum 180 × 16 MB this disk/CPU replay may exhaust the cycle deadline and must fail closed, not skip validation. No external checkpoint or index is trusted. At most seven public GETs per cycle: Gamma (shared with discovery), Open-Meteo forecast, exact YES-token CLOB book, exact NO-token CLOB book, AWC and, only after an available AWC response plus terminal Gamma payout, Data API token lookup and resolution. Both books are bound to the same Gamma condition and their respective ordered outcome tokens; their string millisecond timestamps must be within 120 seconds before to 5 seconds after acquisition, and price/size levels must be valid positive decimal strings (price ≤ 1). The `book` key retains the historical YES capture; new rows add `book_no` with raw body, URL, receipt time and SHA-256. `book_evidence.No` is `verified_book` only with a validated nonempty NO ask list; empty asks yield `unverified_no_ask`. A bounded CLOB 404 with the exact documented `No orderbook exists for the requested token id` JSON body, or a NO-book timeout, retains upstream evidence and marks `unverified_no_book` or `unverified_timeout` respectively; unexpected 404, changed condition/token/timestamp, malformed levels and other upstream errors abort without append. These statuses never imply a fill, executable size after receipt, or P&L; YES-only legacy rows retain their original replay/finality meaning. NO-book absence does not change the settlement label when independent existing AWC/Gamma/Data API prerequisites are met. Each read has a 10-second socket / interrupting 12-second wall limit, a 60-second total cycle limit, no redirects/ambient proxies or credentials, and source-specific byte caps (Gamma 512 KB, forecast 128 KB, each CLOB book 256 KB, AWC 128 KB, each Data API 64 KB). Combined raw-response ceilings are 1,408,000 bytes; sixfold worst-case JSON escaping is 8,448,000 bytes plus bounded metadata. The 16 MB serialized-row ceiling includes JSON escaping and metadata and is checked **before** publication; reads apply the same ceiling. At most 180 rows consume 2.88 GB of tape (excluding filesystem overhead). The 180-cycle, 45-calendar-day, and 30 same-venue-corroborated **unique event-day** caps are enforced before network. One event-hour is captured at most once. Output is restricted to the approved research root with no-follow descriptor walks and atomic exclusive append; old tape entries are never rewritten. The hash chain detects accidental/intermediate edits but not adversarial replacement of the last row. The first candidate manifest is pinned by a complete successful cycle, not by discovery alone; invalid discovery fails closed without publishing a row. No automatic scheduling or retries.

Successful captures retain HTTP status, exact UTF-8 response body, URL, SHA-256, request/acquisition times and response Date. AWC 204 or timeout retains upstream evidence as `captured_partial` and leaves observation/label unverified. Other upstream failures refuse an append. For terminal Gamma, Data API reads are persisted; timeout/malformed/unavailable replies are recorded as unverified, not silently promoted. A `venue_corroborated_final_binary` label requires Gamma binary payout, exact both CTF tokens' condition/event/slot/opposite identities and complementary Data API final prices, plus an exact `resolved` condition row ([public Data API contract](https://docs.polymarket.com/market-data/public-analytics#market-resolution)). The cap replays recorded Gamma and Data API bytes and validates token and condition resolution; a claimed label status, Gamma-only label or malformed Data API body never counts. Both APIs are Polymarket-operated: this is **same-venue corroboration, not independent on-chain UMA verification** or proof of AWC correction chronology or Weather Underground fallback. Open-Meteo forecast issue time remains unknown (`first_available_at` is receipt, never retroactive issuance). These rows establish a source/finality **evidence campaign**, not a profitable strategy: a 30-day tape dominated by non-executable lower-tail books does not measure center-rung edge either. Evaluate matched chronological cohorts with both Yes/No executable bid/ask depth at capture, fees, fill constraints, and realized or conservatively marked P&L before considering any strategy claim. No label makes this live eligible.

**Launch blockers:** The first-seen daily rule and selected rung still need external review and an independently reviewed multi-day manifest. Daily discovery failures (including absent Gamma/invalid rule) still abort without a tape row; the separate unlaunched recurrence runner journals those failed slots with fixed codes and no retry. A historical Karachi October 22 public Data API crosscheck worked, but is not independent on-chain verification. AWC future-day 204 in the existing smoke is no observation. Forecast issuance timestamp and AWC correction-publication/cutoff chronology remain unproven; independent review of revised code and separate recurrence authorization are required. Do not launch recurring service or change funded execution/profile flags.

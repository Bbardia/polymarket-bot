# AWC evidence campaign (not launched)

This isolated worktree contains a **manual one-cycle**, public-only evidence collector, not a daemon or trading strategy. No scheduler/service is installed. It supports only the OPKC / Asia-Karachi station and an exact Gamma event/market identity supplied in a JSON config. The example config pins the October 28 event and the SHA-256 of its published rule text; a new event-day requires a separately reviewed event ID, market ID, date, and rule hash. Do not infer a past observation or forecast from a later fetch.

For a reviewed one-shot invocation (not run as a service):

```sh
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign --report
python -m src.v3.awc_campaign --config config/awc-karachi-20261028.example.json --directory data/awc-campaign
```

`--report` reads the append-only tape without fetching. A cycle makes at most four public GETs, each with a 10-second socket timeout and an interrupting 12-second request wall limit (60-second whole-cycle wall limit, including parsing and tape writes), redirects forbidden, ambient proxies disabled, a hard decoded-body byte cap (Gamma 1 MB, forecast 300 KB, CLOB 512 KB, AWC 256 KB), no credential loading or execution imports. Wall limits require a POSIX main thread with no pre-existing SIGALRM timer; unsupported runners fail closed before any fetch. There are at most 180 cycles, 30 **unique officially labeled event-days**, and 45 × 24 hours from the pinned start. A cycle is exclusive-create and fsynced; sequential entries link hashes. Hashes reveal accidental/intermediate-record tampering, not adversarial edits to the last record. One event-hour is collected at most once. Output is restricted to the isolated worktree's `data/awc-campaign` root (or descendants): the collector walks directories with no-follow handles before fetching and again before writing, refuses symlinked tape entries, and opens/creates tape files relative to a checked directory handle. Keep the input JSON under the reviewed research path as well. No automatic event discovery, scheduling, retries or money movement.

Successful source captures store their HTTP status, exact UTF-8 response body, URL, SHA-256, request/acquisition timestamps and response Date when supplied. Gamma binds event/rule/station/market/token; native CLOB identity and timestamp are checked. After those three sources pass identity/shape checks, an AWC HTTP 204 (officially documented as no data) produces a `captured_partial` row: AWC status 204 and empty body hash are retained, with `failure_code: no_data`. An AWC socket timeout produces a partial row with `status: timeout`, `failure_code: timeout`, request/failure timestamps and no invented body/hash. Both leave `observation.status: unavailable`, no temperatures, and `label.status: unverified` even if Gamma supplies terminal payout metadata. Other HTTP errors, malformed/oversized responses, invalid identities and failures of earlier sources still abort without a row. Partial rows consume the event-hour slot; the collector never retries automatically. Open-Meteo's forecast **issue time is unknown**; `first_available_at` is the collector's receipt time, never a retroactive run issuance. AWC raw is parsed for routine, local-day, T-remark/body temperatures, but correction publication/cutoff and Weather Underground fallback remain unproven. Observed maxima are not official settlement. Labels require Gamma `closed`, exact binary payout, and either explicit `resolvedAt` or **both** event and market `automaticallyResolved` with bounded `closedTime`; otherwise `unverified`. A historical resolved Karachi event showed the latter metadata (and no `resolvedAt`). This is the public Gamma payout **as fetched**, not independently verified UMA finality: later disputes/clarifications could change it. The raw Gamma response remains available for independent label adjudication. The label does not certify the weather computation or confer live eligibility.

**Launch blockers:** independent reviewer and parent approval have not happened; there is no reviewed recurrence/event-discovery manifest for 30 unique event-days, no independently verified UMA-final settlement feed, and no reliable forecast issuance timestamp or AWC correction-publication chronology. A future-date AWC 204/timeout is only an explicit absence, not an observation or a resolved day; API availability must be checked before any scheduled campaign. Keep service unstarted until all of these are addressed and the profile/flags are separately reviewed. No live/funded checkout is touched.
